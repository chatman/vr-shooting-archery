# 10 m range hall — Unity / Meta Quest 3

Everything here is generated by `scripts/export_unity.py` (except this file). Rebuild the
hall and re-run the exporter and the FBX, textures, lights and the C# helper all follow.

| File | What it is |
|---|---|
| `range_10m.fbx` | The hall. 15 meshes, one per material, 6,120 triangles, flat-shaded. Unity reads this natively — no package needed. |
| `Textures/*.png` | 9 textures, referenced by relative path. Keep the folder next to the FBX. |
| `RangeSetup.cs` | Editor script: URP materials, the 35 ceiling lamps, colliders. Generated from the GLB, so it can't drift from the model. |
| `lights.json` | The same lamps as plain data — positions in Unity metres, intensity in candela — if you'd rather build them yourself. |
| `range_10m.glb` | The original, for the glTFast route (see the bottom). |

## Import

1. Drag `range_10m.fbx` **and** the `Textures` folder into `Assets/`.
2. Select the FBX. On the **Model** tab:
   - **Scale Factor 1**, **Convert Units ✓** — the FBX is metric and round-trip verified at
     42 × 30 × 6 m, so the hall should read 42 wide in the scene, not 0.42 or 4200.
   - **Generate Lightmap UVs ✓** — required before you can bake, and easy to forget.
   - **Normals: Import** — the hall is deliberately faceted; letting Unity recalculate
     will smooth the chair legs and target housings into blobs.
   - **Materials → Extract Materials…** into a `Materials/` folder, so the fix-up script
     has assets to edit.
3. Drop `RangeSetup.cs` into `Assets/Editor/`.
4. Drag the FBX into the scene, then run, in order:
   - **Tools ▸ Range ▸ Fix Materials (URP)**
   - **Tools ▸ Range ▸ Build Ceiling Lights**
   - **Tools ▸ Range ▸ Add Colliders**

Step 4 is not optional polish. FBX carries a Phong approximation of a material, so
smoothness, metallic, emission and both glass materials arrive wrong — the glazed front
wall in particular imports as an opaque grey sheet.

## Where things are

1 Unity unit = 1 metre. Downrange is **+Z**.

| | |
|---|---|
| Target wall | z = 0 |
| Firing line / bench front | z = −10 |
| Chairs | z = −13 |
| Glazed wall and doors | z = −30 |
| Lanes 1 … 40 | x = −19.5 … +19.5, 1 m apart |
| Ceiling | y = 6 |

Useful spawns: **firing point 23** at `(2.5, 0, -11.75)` facing +Z; **entrance** at
`(4.5, 0, -29)` facing +Z. Set the `OVRCameraRig` there with `Tracking Origin Type =
Floor Level`, and the headset lands at a real standing height against the model.

## Quest 3 notes

**Bake the lighting; don't ship the lamps as realtime.** 35 realtime point lights is not a
Quest budget. `Build Ceiling Lights` already creates them as **Baked** with shadows off —
mark the hall meshes **Static**, then Window ▸ Rendering ▸ Lighting ▸ Generate Lighting.
Starting settings for a room this size: Progressive GPU, **Lightmap Resolution 3** texels
per unit (the default 40 on 2,500 m² of surface will grind for hours and blow past the
memory budget), max size 2048, Compress ✓, Ambient Occlusion ✓.

The `light_panel` material is set to **BakedEmissive**, so the ceiling panels contribute
to the bake by themselves. If you want the cheapest possible setup, delete the 35 lamps
after baking once and compare — the panels alone light the hall convincingly, and the
result is a lightmap either way.

Project settings that matter more than the model: URP with the **Mobile** renderer,
**Linear** colour space, **Vulkan**, **Single Pass Instanced** stereo, MSAA 4×, IL2CPP +
ARM64. Leave post-processing off unless you have budget to spare.

Geometry is not the constraint here — 6,120 triangles and 15 draw calls is nothing for a
Quest 3. Fill rate and lighting are what will cost you.

## Alternative: skip the FBX

If your project already has **glTFast** (Package Manager ▸ Add by name ▸
`com.unity.cloud.gltfast`), import `range_10m.glb` directly instead. It keeps the real PBR
materials, the alpha-blended glass and the punctual lights as authored, so
`Fix Materials` becomes unnecessary. The FBX exists because it needs no packages at all.

## Known limitations

- **Materials are approximations of the source, not scans.** They carry base colour,
  smoothness and metallic — there are no normal, roughness or AO maps, because the hall
  was authored procedurally rather than textured from photographs.
- **No LODs, no light probes, no reflection probe.** For a room you stand in, LODs buy
  little; a reflection probe is worth adding if you keep the glass wall glossy.
- **Colliders are mesh colliders on the shell and furniture.** Fine for a static room, but
  if you add physics props, give the floor a box collider instead — cheaper by far.
- **The doors are closed leaves in real openings.** Hide the `door_glass` object and the
  doorway is walkable; there is no hinge rig or animation.
